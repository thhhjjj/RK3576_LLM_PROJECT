# 第五阶段：做到哪一步

> 依据 [project.md](../project.md) 的 **frpc** 层。**排期上属添头，优先级最低**。本阶段结束时：arm64 `frpc` 在 rootfs 里，UI 能启动/杀掉；**默认不起、不写开机脚本**；蜂窝手机打开公网地址能完成一轮 WebSocket 对话。仍不做拼音输入法；公网 HTTP 上不做 WebBLE。

见 [PHASE4.md](./PHASE4.md)。**不要把「公网能聊」绑成 PHASE3/6/7 硬门**；主线走完再视需要装隧道。

## 完成线（摘要）

1. rootfs 含 arm64 **frpc**（约几十 MB 级，非常驻则不是内存大户）。  
2. UI 按钮：**启动** / **停止（kill）**；默认关闭；**不进**开机自启。  
3. 关掉时回收进程，无僵尸、无残留监听误解。  
4. 隧道验证：手机用**蜂窝**打开公网地址 → 页面 + **WebSocket** 能完成一轮对话。  
5. frp **HTTP** 类型须能升级 WebSocket；拿不准则改 **TCP 整端口转发**，少一层代理。  
6. **边界**：公网纯 HTTP **不做** WebBLE；若公网页也要 WebBLE → 隧道改 TLS，且手机须在板旁（射频仍走蓝牙，不经 frp）。

## 四块各自停在哪

| 块 | 做到这个程度 | 停在这里 |
|---|---|---|
| frpc 二进制 | 进 rootfs 或 overlay 可装路径固定 | 不强制常驻、不做复杂多隧道产品化 |
| UI 控制 | 一键起停 + 简短状态（运行中 / 已关） | 不做完整 frp 配置编辑器 |
| 公网通路 | 蜂窝一轮 WS 对话 | 不绑 WebBLE；不默认开机暴露 |
| 安全 | 默认关；文档写清暴露面 | 不做完整鉴权网关 |

## 细分步骤（开工后往 PHASE5_DID 记）

1. 选定 frp 服务端与客户端配置模板（HTTP 升 WS 或 TCP 转发 `:8765`）。  
2. 把 `frpc` 装进镜像或可推送路径；版本与 arch 记 DID。  
3. `llm_panel`（或小助手脚本）起停 frpc；UI 按钮接通。  
4. 确认**无** systemd/init 默认拉起。  
5. 蜂窝压测：公网 → WS 试问一轮；断隧道后本地屏/局域网 WS 仍可用。  
6. 收口：DID 写配置名、端口、是否 TCP 兜底、关闭后无残留进程。

## 明确不做（本阶段）

- 开机默认启动 frpc  
- 公网 HTTP 上的 WebBLE  
- 拼音输入法 / 完整软键盘  
- 把「必须公网可聊」写成 PHASE1～4 的硬门

## 与前后阶段

- **之前**：PHASE3 局域网 WS；PHASE4 近场 BLE。远处无蓝牙时走 WS；有 frpc 后远处可走公网 WS。  
- **之后**：PHASE6 GPU 渲染（可提前做，见 [PHASE6.md](./PHASE6.md)）、PHASE7 NPU/体验 — 均不挡本阶段是否做完（本阶段本身也可跳过）。
