# 第二阶段：做到哪一步

> 依据 [project.md](../project.md) 的本地推理层。当前试跑钉 **Qwen3.5-2B VLM @1024**（先文本、后视觉）；阶段结束时本机屏能多轮对话，自动/手动压缩后还能继续。WebSocket、GATT、云端 GLM、frpc 都还没开始。

第一阶段完成线见 [PHASE1.md](./PHASE1.md)；已做记录与内存基线见 [PHASE1_DID.md](./PHASE1_DID.md)。**第一阶段不过线，不进本阶段。**

## 完成线

上电后同时满足下面七条，才算第二阶段完成，才允许进第三阶段：

1. `librkllmrt`（及依赖）在 rootfs 里，与 PC 侧 RKLLM toolkit **同大版本**。
2. 开机进程按硬顺序：**先加载默认 `.rkllm` 并建好会话句柄，再启动 LVGL**。禁止「先满 UI、第一次提问才 load」。
3. 本机屏能发一条问题，流式看到回答；对话框、上下文占用、token/s 有真实数值（不再是 `—`）。
4. 默认模型 **Qwen3.5-2B VLM（语言侧 W4A16_g128 @1024）** 能多轮对话；历史到水位后自动压缩，手动压缩按钮真正销毁并重建会话。
5. 压缩后还能继续答；`MemAvailable` 在压缩后回升或不单调下降；无内核 OOM、无 NPU 连续内存分配失败导致进程退出。
6. 推理进行中，六项系统指标（内存 / CPU / NPU 负载 / NPU 温度 / GPU / 网速）仍约 1 秒刷新；NPU 负载在推理时升高，空闲回落。
7. 本地 / 云端开关在本阶段：**云端仍只改 UI 态或不接真实请求**；不打开监听端口、不注册 GATT、不写 frpc。

当前试跑以 **Qwen3.5-2B VLM 文本通路** 为主验收；视觉、1.7B 对照、2048 压测另记，不挡「能聊 + 能压缩」这条线。

## 四块各自停在哪

| 块 | 做到这个程度 | 这一阶段停在这里 |
|---|---|---|
| RKLLM 运行时 | overlay 装好同版本 `librkllmrt` + 默认 `.rkllm`；能 load / run / abort | 不写 Buildroot 永久上游包也可以，但路径与版本要写死可复现 |
| 会话与压缩 | ChatML 拼 prompt；自动 + 手动压缩同一套「销毁句柄 → 重建 → prefill」 | 不做跨进程持久化历史；不落盘 API Key；不双句柄并存 |
| 与 LVGL 衔接 | 回调只入队；`lv_async_call` / 投递刷新对话框与 token/s | 回调里禁止画屏、写 socket、写 GATT、做压缩 |
| 模型矩阵 | 冒烟 → 1.7B 正式同驻 UI | 3B 对照、3.5-2B 视觉、云端 SSE 留给后阶段或可选压测 |

## 从第一阶段继承的硬前提

- 屏 720×1280、触摸、Seekwave WiFi/`hci0`、裁剪 Buildroot、`llm_ctrl`、`llm_panel` 六项指标 + 中文已过。
- **内存基线（2026-10-17）**：LVGL+中文常驻时 **MemAvailable ≈ 3780 MB**（面板约 `118 / 3898 MB`）。第二阶段每次换模型 / 压测都要再记加载后与跑满后的 `MemAvailable`。
- PHASE1 已留后阶段门：`libwebsockets`、`libcurl`、BlueZ 在 rootfs 里可以先不调用；**`librkllm` 本树无正式 Buildroot 包，本阶段用 overlay / 手工安装塞进 rootfs**。
- CMA / DMA heap 仍保持 SDK 默认；加载失败再调，不预先砍小。

## RKLLM 版本与模型

| 角色 | 模型 | 量化 / 上下文 | RKLLM | 本阶段要求 |
|---|---|---|---|---|
| **当前试跑（已定）** | **Qwen3.5-2B VLM** | W4A16_g128 @1024；语言 `.rkllm` + 视觉 `.rknn` | **≥ 1.3.1** | 先文本「试问」；视觉后接 |
| 量产备选 / 对照 | `Qwen3-1.7B-Instruct` | W4A16 @1024 | 1.2.x+ / 1.3.x | 内存更省时的正式默认候选 |
| 通路冒烟 | `Qwen2.5-0.5B` / `Qwen3-0.6B` | W4A16 @1024 | 同大版本 | 可选，证明 load / 流式 |
| 对照（可选） | `Qwen2.5-3B` | W4A16 @512~1024 | 同大版本 | **不与 LVGL 长期并行**作量产默认 |

口径：

- **试跑包**：社区 `HanzoHuang/Qwen3.5-2B-RKLLM` 的 `RK3576/` 成对文件 → `models/default.rkllm` + `models/vision.rknn`（见 `rkllm_autoload/README.md`）。
- `.rkllm` / `.rknn` 必须 `rk3576` 同目录一对。3588 包不能直接跑。
- PC toolkit 与板端 `librkllmrt.so` **同大版本（现 1.3.1）**。
- `max_context_len` 写进模型文件；运行时只能 ≤ 该值。另导 2048 仅压测。
- thinking 默认关；需要时再做高级开关。
- 口语「Qwen3 2B」应对 **Qwen3-1.7B**；真 2B 是 **Qwen3.5-2B**（本板试跑用后者 VLM）。

## 进程内启动顺序（硬口径）

NPU / RKLLM 需要较大块连续物理内存。`MemAvailable` 够用不等于分配成功。

1. 初始化加载模型所必需的最小环境（含 DRM/GEM 若 runtime 依赖）。
2. **`rkllm_init` / load 默认 `.rkllm`，建好会话句柄。**
3. **再启动 LVGL**（控件、字库、指标定时器、对话框）。
4. 其后本阶段不再挂 WebSocket / BLE。

换模型：先 abort → 等回调结束 → **销毁旧句柄** → 再 load 新模型 → 恢复 UI 会话态。禁止双句柄叠权重。

与 PHASE1 现网 `S90llm_panel`「直接起 UI」冲突时：**改启动脚本 / 主程序入口**，使正式二进制内部保证上述顺序，而不是先起一个空面板再异步 load。

## 封装与线程边界

封装最小集合：

- load / destroy 模型与会话
- 按 ChatML 拼 prompt（原始 prompt 接口，避免再套一层 template）
- 流式 run；回调里只把 token（或结束/错误事件）写入**有界队列**
- abort；模式切换与停止时先 abort，再动句柄
- 从回调计数 ÷ 墙钟得到 token/s，投递到 UI

消息列表只在进程内存。system 提示固定保留（嵌入式 Linux 助手口径见 [project.md](../project.md)）。

**回调里禁止**：画 LVGL、写 socket、写 GATT、做压缩、阻塞 IO。

LVGL 不是线程安全的：推理线程只许 `lv_async_call` 或等价投递；采集指标仍放 LVGL 定时器。

## 压缩（自动 = 手动同一函数）

水位用运行时回报的 token 数，**不用** `strlen/4`。建议历史达到 `max_context` 的 **70%** 触发自动压缩。

压缩步骤写死：

1. 保留 system；删最早的用户/助手轮次，直到低于水位。
2. abort（若仍在生成）。
3. **销毁**当前会话句柄（必要时整模型句柄按 runtime API 要求销毁）。
4. **重建**会话，整段 prefill 保留下来的历史。
5. 函数重入保护：压缩进行中忽略第二次自动触发；手动按钮与自动共用锁。

压缩后 UI：对话框仍显示保留的历史摘要或全文（实现自定，但必须可继续问）；上下文占用数字下降；`MemAvailable` 应回升或至少不再单调掉。

### 当前进度：压缩必须异步（体验已踩坑）

**现象（2026-10-19）**：点「压缩」或低水位自动压缩时，整屏 LVGL 卡住（指标停刷、触摸无响应），直到 destroy/重载/prefill 结束。

**根因**：`main.c` 的 `on_ui_compress` / `metrics_timer_cb` 在 **LVGL 线程**里同步调用 `session_compress()`；该函数含整模 reload，耗时长。试问已走 worker，压缩还没。

**要求（未做则压缩体验不过）**：

1. UI / 低水位只投递「压缩」任务，立刻返回；可先写「压缩中…」。
2. worker（或与 ask 同一条后台线程）执行 `session_compress`。
3. 完成 / 失败经 `tokq`（`TOKQ_STATUS` / `TOKQ_ERROR`）回主线程刷新对话区。
4. 压缩中：拒新 ask、忽略重复压缩触发（与现有 `compressing` 闩锁对齐）。
5. 验收：压缩全程六项指标仍约 1 秒刷新；触摸不假死。

细节与复现记 [PHASE2_DID.md](./PHASE2_DID.md)。

## 内存保护

- 周期读 `MemAvailable`（可与指标定时器同周期或稍慢）。
- 低于阈值（建议先 **200MB**，按曲线改）时：UI 告警，并**异步**触发一次压缩；压缩中不重入。
- 每次：冒烟加载后、1.7B 加载后、多轮跑满后、压缩后再各记一笔，写入 [PHASE2_DID.md](./PHASE2_DID.md)。

## 后续工作（不挡本阶段完成线）：再挤 Available

> 目标：给更长上下文 / 更大模型余量腾 **几十～约一两百 MB** `MemAvailable`。不替代换更小 `.rkllm` 或 `embed_flash`；也**不**把「裁服务」写成 10k 上下文的充分条件。

PHASE1 已做过一轮 Buildroot 裁剪；本项是 **第二轮：关无用用户态常驻**，在文本通路与压缩异步过线之后做。

| 做 | 不做 / 红线 |
|---|---|
| 盘点开机自启与常驻进程（`systemd`/`init.d`、多余 daemon） | 不砍 `ROCKCHIP_RKNPU`、DRM、CMA/DMA heap、Seekwave WiFi/BT、指标用的 procfs/sysfs |
| 确认无 Docker / 桌面会话 / 未用中间件则卸或禁用 | 不提前为「省内存」砍小 CMA |
| 关本阶段用不到的服务（未开 WebSocket/GATT/frpc 前勿常驻相关栈） | 不关后续阶段仍要的包本身（可先禁用自启，包可留在镜像） |
| 裁前 / 裁后各记一笔：无模型基线与 **模型加载后** 的 `MemAvailable`、面板已用/总计 | 不把预期收益写成固定数字；以板上两次对比为准 |

验收记入 [PHASE2_DID.md](./PHASE2_DID.md)：列出关掉的单元名、Available 差值。收益量级预期 **几十～约 100～200 MB**；不够再走换 1.7B / 开 `embed_flash` / 更短真窗口 + 压缩。

## 不过线就不进第三阶段

对应 [project.md](../project.md) 验收第 2 条。下面任意一条成立，第二阶段就不算完成：

- 只有冒烟模型能聊，1.7B 无法与 LVGL 同驻稳定多轮
- 先开满 UI 再首次提问才 load，且存在可复现的 NPU/CMA 分配失败（未按硬顺序改掉）
- 压缩后无法继续对话，或双句柄并存导致 OOM
- **压缩在 LVGL 主线程同步执行，导致整屏假死**（指标停、触摸卡）
- 回调里直接操作 LVGL / 网络导致卡死或崩溃
- 为了「演示完整产品」提前开了 WebSocket 监听、GATT 或云端 SSE，且把阶段出口绑在它们上面
- 未记录 1.7B 加载后与压缩后的 `MemAvailable`

## 细分步骤

按这个顺序做。每一步过了再做下一步。版本与路径记进 [PHASE2_DID.md](./PHASE2_DID.md)。

### 1. 运行时进 rootfs

1. 确认 PC toolkit 与目标板 `librkllmrt` 大版本一致；写明版本号（例如 1.2.x 或 1.3.x）。
2. 用 overlay 或 `prepare.sh` 把 `librkllmrt.so`、必要依赖、默认模型目录装进 rootfs（如 `/opt/rkllm/` 或 `/usr/lib` + `/usr/share/rkllm/`）。路径写死到程序或配置，不靠交互式找文件。
3. 重编 / 重刷 rootfs（或 adb 临时推送做通后再固化进镜像）。
4. 板上 `ldd` / 最小 C 程序能 `rkllm` 创建句柄（或官方 demo 跑通），不依赖 LVGL。

### 2. 冒烟模型（0.5B / 0.6B）

5. 导出或放入 rk3576 的 W4 @1024 冒烟包。
6. 命令行或最小程序：load → 问一句 → 流式打印 → destroy。记下加载后 `MemAvailable`。
7. 人为堆历史触发一次压缩（或手动调用压缩函数）：销毁重建后还能再问一句。

### 3. 改 `llm_panel` 进程结构

8. 拆线程 / 队列：推理回调 → 有界队列 → LVGL 侧消费。
9. 主程序改为：**先 load 默认模型，再 `ui_create`**。调整 `S90llm_panel` 若需要（仍只启一个主进程）。
10. 接通对话框流式刷新与 token/s、上下文标签。
11. 压缩按钮绑真实压缩；去掉「只改字」的 PHASE1 行为。
11b. **（当前缺口）压缩异步化**：按钮 / 低水位 / 70% 水位只投递任务；worker 跑 destroy→create→prefill；`tokq` 回写；压缩中拒 ask。板上确认压缩时 LVGL 不卡。
12. 确认回调路径无 LVGL API、无阻塞网络。

### 4. 正式默认 Qwen3-1.7B @1024

13. 导出：`Qwen/Qwen3-1.7B-Instruct`，W4A16，`target_platform=rk3576`，`max_context_len=1024`。
14. 替换默认模型；开机自动 load 成功。记加载后 `MemAvailable`。
15. 本机屏多轮中文对话；看 NPU 负载与温度是否合理。
16. 打到约 70% 上下文，确认自动压缩发生；再按一次手动压缩。
17. 压缩后继续问答；记压缩后 `MemAvailable`；确认无 OOM、进程不退出、指标仍刷。

### 5. 内存与异常路径

18. 实现 `MemAvailable` 低水位告警 + 触发压缩（阈值先 200MB）。
19. 生成中点「停止」（若有）或切换本地开关：先 abort，等回调结束再动句柄。
20. 故意缺模型文件 / 损坏文件：UI 有错误状态，进程不崩，不把阶段卡死在黑屏。

### 6. 可选压测（不挡出口）

21. 另包 2048：跑满与压缩；失败则正式锁 1024，记录原因。
22. 若 toolkit ≥ 1.3.0：试 Qwen3.5-2B 文本包；记内存；视觉 `.rknn` 本阶段可不挂。
23. 3B 对照仅短时压测，不设为默认开机模型。

### 7. 收口

24. 重启冷启动：不手工 `insmod`、不手工拷 so，默认 1.7B 可聊，压缩可用。
25. 核对完成线七条全部成立；第三阶段才允许开 WebSocket。
26. 把版本、路径、各次 `MemAvailable`、已知问题写入 [PHASE2_DID.md](./PHASE2_DID.md)。

### 8. 后续：再裁 rootfs / 关无用服务（不挡出口）

27. 列出当前常驻：`ps` / `systemctl`（或板端等价），标出 Docker、桌面、未用 daemon。
28. 禁用或卸载确认无用的自启单元；保留 PHASE 后续仍要的软件包时可只关自启。
29. 冷启动后记：无模型 Available、加载默认模型后 Available / 面板已用；与裁前对比写入 DID。
30. 若 Available 无明显回升：记录「已排查无大户」，停止空砍；改走模型侧手段（更小权重、`embed_flash`）。
